## 1. Diagnóstico del Pipeline Anterior

En la auditoría de Misión 1B se identificaron dos desajustes en el flujo de empaquetado:
1. **Ejecución Prematura del Validador:** `scripts/validate-package-resources.mjs` se invocaba al final de `esbuild.config.mjs`, cuando únicamente se había generado el frontend en `dist/`, pero el servicio Node.js en `build/bundled-service/` aún no había sido compilado ni copiado. Esto requería suposiciones o ignorar advertencias sobre archivos faltantes del servicio.
2. **Falta de Validación del Contenedor Final `.ipk`:** La verificación se limitaba a revisar los directorios del sistema de archivos local (`dist/` y `build/bundled-service/`), pero no comprobaba el archivo `.ipk` real generado por `ares-package`. Errores en filtros de exclusión (como `-e "*preview-libs.js"`), rutas relativas dentro de `data.tar.gz` o corrupción de binarios ELF no eran auditados en el artefacto distribuible.

## 2. Reordenamiento del Pipeline en `build.sh`

El script de empaquetado `build.sh` fue reestructurado en un flujo secuencial estricto de 5 fases deterministas:

```
┌────────────────────────────────────────────────────────┐
│ 1. Compilación del Frontend (dist/)                    │
│    npm run build (tsc + esbuild chrome53 + compat gate)│
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│ 2. Compilación del Servicio (build/bundled-service/)   │
│    tsc ES5 + Node 0.12.2 compat gate + copia de assets │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│ 3. Validación de Recursos Previa al Empaquetado        │
│    node scripts/validate-package-resources.mjs dist ...│
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│ 4. Empaquetado Oficial (ares-package)                  │
│    ares-package --no-minify -e "*preview-libs.js" ...  │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│ 5. Inspección Forense del Archivo .ipk Resultante      │
│    node scripts/validate-package-resources.mjs --ipk   │
└────────────────────────────────────────────────────────┘
```

### 2.1 Código Implementado en `build.sh`
```bash
# 1. Compilación del frontend
info "Building app (type-check + esbuild bundle)..."
npm run build

# 2. Compilación del servicio Node.js
info "Building service..."
rm -rf build/bundled-service
npx tsc -p bundled-service/tsconfig.json
node scripts/service-compat-gate.mjs build/bundled-service
cp bundled-service/package.json build/bundled-service/
cp bundled-service/src/services.json build/bundled-service/
mkdir -p build/bundled-service/setup
cp bundled-service/src/setup/setup-page.html build/bundled-service/setup/

# 3. Validación de recursos previa al empaquetado
info "Validating package resources before packaging..."
node scripts/validate-package-resources.mjs dist build/bundled-service

# 4. Empaquetado IPK
info "Packaging IPK..."
ares-package --no-minify -e "*preview-libs.js" dist build/bundled-service -o .

IPK=$(ls -t *.ipk 2>/dev/null | head -1)
[ -n "$IPK" ] || error "No .ipk package generated by ares-package"
info "Built: $IPK ($(du -h "$IPK" | cut -f1))"

# 5. Inspección y validación del archivo IPK empaquetado
info "Validating packaged IPK archive..."
node scripts/validate-package-resources.mjs --ipk "$IPK"

# 6. Manifiesto Homebrew
info "Generating Homebrew Channel manifest..."
npm run manifest -- "$IPK"
```

## 3. Extensión del Validador de Paquetes (`validate-package-resources.mjs`)

El validador se mejoró con un motor de inspección de archivos `.ipk` implementado en JavaScript puro (sin dependencias externas ni herramientas nativas de Linux):
* **Parser de formato `ar` de Unix:** Lee los encabezados de 60 bytes y extrae `debian-binary`, `control.tar.gz` y `data.tar.gz`.
* **Descompresor `zlib.gunzipSync`:** Descomprime `data.tar.gz` en memoria.
* **Parser de bloques UStar (tar):** Itera sobre los bloques de 512 bytes de la cabecera tar, decodificando nombres de archivo y tamaños octales.
* **Comprobación de Recursos Clave:**
  * Confirma presencia de `appinfo.json`, `index.html`, `js/app.js` (o `bundle.js`), `css/main.css`, `icon.png`.
  * Comprueba que cada etiqueta `<script src>` y `<link href>` en `index.html` existe físicamente dentro del IPK.
  * Confirma presencia de `package.json`, `services.json`, `index.js` y `setup/setup-page.html` en el árbol del servicio.
* **Regla Anti-Preview:** Emite error crítico si el archivo `preview-libs.js` aparece en cualquier parte del paquete o si está referenciado en `index.html`.
* **Auditoría de Arquitectura de Binarios ELF:**
  * Si el paquete contiene binarios ejecutables o librerías compartidas (archivos con cabecera `\x7fELF`), inspecciona `e_ident[EI_CLASS]` (debe ser `1` = 32-bit) y `e_machine` (debe ser `40` = `EM_ARM`).
  * Rechaza cualquier binario x86, x86_64 o ARM64, que causaría fallos de ejecución en el SOC Realtek RTD2870 de webOS 4.
